Пустой query ранее запрещался для всех шагов, хотя discovery/taste_neighbors/library и Last.fm/Yandex similar_tracks его не используют. Теперь UsesContextQuery описывает только фактически контекстные возможности; CanonicalSearch заменяет игнорируемый текст на context. Ни источник, ни бюджет, ни стратегия не подменяются, дополнительные платные исправляющие вызовы не выполняются.

catalog_search/artist_tracks по-прежнему требуют непустой запрос до 120 Unicode-символов. Ошибка сообщает индекс шага, provider/capability и фактическую длину без вывода текста. Schema содержит maxLength для query и reason; промпт описывает, какие инструменты используют seed, а какие текст. ID/scope/budget проверки не ослаблены.

TestDJEmptyContextQueryReachesSourceAndSavesResult проверяет реальный worker: mock-планировщик возвращает similar_tracks с query="", настоящий адаптер вызывает тестовый источник, mock-selector выбирает реальный candidate_id; итог ready, один трек, два модельных вызова к локальному серверу и один вызов источника. Дополнительно покрыты все контекстные каналы, неизменность стратегии/лимита и отказ пустым/длинным текстовым запросам.

Причина конкретного старого ответа не доказана: его raw plan не сохранялся, сообщение объединяло пустые и длинные строки. Исправлен воспроизводимый дефект; возможные дальнейшие ошибки источников и качество музыкальной выдачи этим не проверены. Новых платных вызовов нет.
