# Cryon Intelligence: первая версия

## Включение

Настройки → Музыка → Cryon Intelligence · AI DJ. Выберите провайдера, укажите
точный идентификатор модели и собственный API-ключ, включите переключатель и
сохраните. Поддерживаются OpenAI, DeepSeek, Claude/Anthropic и совместимый Chat
Completions API. Для совместимого API нужен HTTPS endpoint. Для остальных можно
оставить адрес пустым. Модель должна возвращать JSON по заданной схеме;
несовместимый ответ приводит к обычному радио. При смене провайдера/endpoint
ключ требуется ввести заново. Пустое поле сохраняет прежний ключ только для
того же провайдера и адреса.

AI выключен по умолчанию. Подписка на чат провайдера сама по себе не заменяет
API-ключ и API-баланс. Ключ сохраняется в локальном SQLite, без нового механизма
шифрования; UI и универсальный getter настроек его не возвращают. В сторонний
API отправляются только музыкальные метаданные, компактный профиль и реакции,
без URL потоков, локальных путей и ключей музыкальных сервисов.

## Поведение радио

Первый сегмент сразу готовит прежний движок. Фоновый AI DJ планирует до трёх
операций: исследовать существующий граф, использовать библиотеку/историю,
искать в каталоге, запросить похожие треки Last.fm/Яндекса или треки исполнителя
Deezer. Доступные возможности объявляет backend. Яндекс объявляется при токене;
Last.fm — при ключе. Last.fm/Deezer дают метаданные, а воспроизводимая запись
находится через существующий поиск Cryon.

После исполнения планировщика кандидаты объединяются, проходят существующие
блокировки, нормализацию ключей, дедупликацию и ограничение исполнителей.
Второй запрос AI оценивает только этот конкретный пул. Новый сегмент выдаётся
при следующем пополнении очереди, если его контекст ещё актуален. Уже выданная
очередь не переставляется. «Рекомендовано Cryon AI» появляется только на
подготовленном AI сегменте. Причина выбора может быть сокращена интерфейсом.

Бесконечное радио ориентируется на вкус и исследование новых направлений.
Радио по треку хранит исходный seed неизменным на протяжении сессии; этот seed
передаётся обоим AI-этапам. В обоих режимах без AI используется прежний
RelatedTracks, включая его кэш, правила источников и fallback. Существующие
Wails ListRelatedTracks и /v1/recommendations/related продолжают работать;
опциональный DJ подключён отдельным общим HTTP API для Windows и Android.

Пропуск хранится вместе с временем прослушивания. Ошибка загрузки — отдельное
событие, а не дизлайк. Накопленный Taste Profile берётся из существующего
buildTaste: история, избранное, плейлисты, локальные исполнители и явные оценки.
Модели передаются до 20 исполнителей и до 15 доступных локальных жанров;
аудиосигнал модель в этой версии не слушает. Последние реакции и направления
предыдущего плана дают контекст следующему циклу.

## Ограничения и расходы

- Один фоновый worker; до трёх каналов выполняются параллельно. Общий deadline
  45 секунд, отдельный AI-запрос — 20 секунд; автоматические HTTP-повторы отключены.
- До 40 кандидатов, 120 символов запроса и 160 символов причины. На один AI-ответ
  запрашивается не более 2500 output tokens. Входной контекст ограничен 64 КиБ,
  JSON ответа — 64 КиБ, HTTP body — 256 КиБ; неоднозначный JSON отклоняется.
- По умолчанию 100 попыток подготовки сегмента в сутки UTC, максимум настройки —
  500. Счётчик сохраняется до начала запроса, включая неудачные попытки. Ошибка
  включает минутный cooldown. На сегмент приходится максимум два AI-запроса.
- Готовый сегмент живёт до 10 минут; смена сессии, профиля или настроек делает
  его неактуальным. При отсутствии подходящего сегмента работает baseline.
- Статус показывает попытки за день и токены, сообщённые API; часть провайдеров
  не сообщает usage. Это не денежный счётчик и не гарантия суммы списания.

SQLite хранит сессии, идемпотентные события, исходные пулы с provenance и оба
плана с ревизиями. Полный сброс данных удаляет их вместе с ключом. `/v1/intelligence/config`
возвращает обезличенный статус: prepared/fallbacks текущего запуска, usage дня и
счётчики событий. `unfamiliar_artist_likes` — число разных треков с лайком, артист
которых отсутствовал в полном локальном профиле при подготовке. Это измеримый
признак полезного открытия, а не доказательство, что человек раньше не знал музыку.

## Проверка и развитие

HTTP-тесты проверяют два AI-этапа без реальных ключей: корректные контракты,
ошибки API, отмену, лимиты, устаревшие ревизии, кандидатные ID, provenance и
локальное хранение. Качество музыкальной подборки конкретной модели нужно
оценивать на реальных прослушиваниях. Техническая приёмка не утверждает улучшение
вкусовой точности по сравнению с прежним алгоритмом.

Векторный поиск и анализ звучания остаются последующим этапом. В этой поставке
нет нового сервера рекомендаций, Python, Rust, Essentia или аудиоэмбеддингов.
Лицензии добавленных Go-библиотек: [third-party/NOTICE.md](third-party/NOTICE.md).
План, отметки и результаты проверок: [cryon-intelligence-plan.md](cryon-intelligence-plan.md).


### Видимый результат и постоянные запреты (v0.2.32)

Главная → «Подобрал AI Cryon»: последние подготовленные AI треки, причины выбора,
время обновления, статус и кнопка «Подобрать музыку». Подготовка выполняется в фоне;
страница обновляется автоматически. Треки сохраняются локально между запусками.
Обычные треки не получают метку AI. Без включённой модели обычное радио сохраняется.
Реакции, пришедшие за время запроса к модели, больше не уничтожают готовый сегмент:
перед выдачей повторно проверяются запреты, текущая очередь и прослушанные ID.

Меню трека → «Не рекомендовать трек» / «Не рекомендовать исполнителя».
Запрещённые строки перечёркнуты, воспроизведение недоступно, очередь очищается.
Запреты артистов сохраняются в существующем feedback-хранилище ключом `artist|*`;
их можно снять в Настройки → Музыка → «Не рекомендовать исполнителей».
Они проверяются в общей фильтрации, включая кэш, AI и совместные записи.

История выдач `reco.exposures` ограничена 5000 записями/30 днями. Треки за последние
7 дней уступают новым кандидатам. Это мягкое ограничение: при малом каталоге повторы
возможны. Порядок меняется по дню; AI-порядок после ранжирования не перемешивается.
Готовый пул радио читается до сетевого поиска и не обрезается после каждого refill.
Сетевой бюджет обычного радио и пользовательских подборок — 12 секунд; это не
гарантия времени запуска воспроизведения, которое зависит ещё от получения потока.
