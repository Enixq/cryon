## Подтверждённые факты

В установленном Windows-приложении v0.2.35 последняя задача завершилась на planning с общим сообщением ошибки AI API, found/candidates/selected=0. Реальная сохранённая модель была доступна в бесплатном GET /models, ключ принимался. Новый платный поиск без разрешения не запускался.

`TestTransportDeadlineIsNotHiddenBySDKRetry` воспроизвёл дефект: исходный DeadlineExceeded превращался в «Не удалось получить ответ модели; проверьте соединение и поддержку API». Обёртка SDK автоматически предпринимала повтор, transport его блокировал, и наружу выходила последняя ошибка запрета повтора. Старый HTTP timeout составлял 35 секунд. Отдельно в приложении глобально отключено обновление React Query при возврате фокуса; DJ не переопределял эту настройку, а фоновые опросы были выключены по умолчанию. Это позволяло оставлять старый экран planning, пока приложение скрыто.

## Изменения

`internal/intelligence/providers/openai_http.go` выполняет единственный HTTP-запрос без автоматического повтора для OpenAI/совместимых API. Собственный интерфейс Director PlanSearch/Select, JSON Schema, строгая проверка scope/IDs, лимит ответа 2500 и входа/ответа сохранены. Anthropic остаётся на SDK с отключёнными повторами. Ограничение одного вызова теперь задаётся контекстом 60 секунд; общий лимит задачи остаётся 180 секунд.

Для семейства reasoning-моделей gpt-5/o1/o3/o4 задаются max_completion_tokens и reasoning_effort=low, для остальных — max_tokens. Это снижает расход времени на скрытые рассуждения; совместимость параметра проверена реальным запросом к настроенной пользователем модели. Другие нестандартные модели всё ещё могут отклонять параметры; автоматического платного запроса с другими настройками после ошибки нет.

Добавлена обработка JSON без finish_reason, а также ограниченного SSE-ответа от шлюзов, которые возвращают поток вопреки stream:false. Пустой ответ, несовместимый JSON, исчерпание лимита и тайм-аут различаются; тело ошибки, ключ и URL с секретами в сообщение не попадают. Usage читается из total_tokens либо суммы prompt/completion.

Диагностика задачи содержит requestDeadlineAt. Интерфейс показывает, что сейчас ожидается ответ модели, сколько осталось до предела и что поиск по музыкальным источникам ещё не начат. Вместо обещания треков после одного POST выводится, что появится результат либо причина ошибки. Для общего запроса djCollection включены фоновый опрос, принудительное обновление при фокусе/восстановлении сети и staleTime=0. Страница и панель используют одинаковые настройки.

## Проверки и предел доказательства

С разрешения пользователя выполнен **ровно один** запрос PlanSearch новой реализацией к сохранённой модели gpt-5.6-terra с локальным снимком вкуса, контекстом последней сессии и описанием поисковых каналов. Настройки и ключ пользователя не изменялись. Результат: **13 662 мс, 3356 total tokens, четыре шага, ValidateSearch прошёл**. Это доказывает получение пригодного плана от реального API, но не качество окончательной подборки: поиски по этому плану и второй LLM-вызов не запускались. Диагностический запрос выполнялся отдельно от приложения, поэтому его расход не прибавлен к счётчику задач внутри Cryon.

Пройдены полный go test ./..., 110 frontend-тестов, TypeScript/Vite. Добавлены проверки потери transport timeout, JSON/SSE, пропущенного finish_reason, usage, отсутствия повторных HTTP-запросов и обновления незавершённой задачи при возвращении фокуса с глобальными настройками реального приложения.

Причину каждого старого обращения ретроспективно установить нельзя: прежняя версия не сохраняла транспортную причину. Исправление воспроизводимого дефекта и успешный новый запрос не доказывают, что внешняя сеть или сервис никогда больше не дадут сбой.
