# Cryon

**Кроссплатформенный музыкальный плеер-агрегатор**: один интерфейс для нескольких источников музыки — YouTube Music, SoundCloud, Яндекс Музыка, Spotify и локальных файлов.

> **Скачал — и работает.** Поиск, воспроизведение и рекомендации запускаются сразу после установки, **без единого ключа и токена**. Подключение Yandex / Last.fm / Spotify — по желанию: они лишь расширяют каталог и делают рекомендации точнее.

- **Desktop (Windows)** — нативное приложение на [Wails 2](https://wails.io) (Go + WebView2), собирается в `.exe` с NSIS-установщиком.
- **Android** — автономное приложение: весь Go-бэкенд встроен в устройство (gomobile → `.aar`) и поднимает локальный HTTP-сервер на `127.0.0.1`; Kotlin-оболочка грузит фронтенд в WebView. ПК и внешний сервер не нужны.

## Скачать и запустить

Готовые сборки — на вкладке [Releases](https://github.com/Enixq/cryon/releases) (собираются автоматически при публикации тега `v*`, см. [.github/workflows/release.yml](.github/workflows/release.yml)):

| Файл | Платформа | Как запустить |
|---|---|---|
| `Cryon2-<версия>-windows-installer.exe` | Windows 10/11 | Установщик (NSIS) — обычная установка |
| `Cryon2-<версия>-windows-amd64.exe` | Windows 10/11 | Портативный `.exe` — просто запустить |
| `Cryon2-<версия>-android-arm64.apk` | Android (arm64) | Скопировать на телефон и установить (нужно разрешить «установку из неизвестных источников») |

После запуска можно сразу искать и слушать музыку. Чтобы появились рекомендации, добавьте папку с локальной музыкой в **Настройках** или послушайте пару треков — большего не требуется.

## Что работает без настройки

Всё нужное для «скачал и слушаю» — бесключевое:

| Возможность | Как это работает без ключей |
|---|---|
| 🔎 **Поиск и воспроизведение** | YouTube (официальный API → Bing → `yt-dlp`) и SoundCloud — оба без ключа |
| 📁 **Локальная библиотека** | Сканирование папки, метаданные, обложки, воспроизведение файлов |
| 🧠 **Рекомендации** | Бесключевой граф похожести [Deezer](https://developers.deezer.com/api) (кто на кого похож / топ-треки / чарт) → кросс-источниковый подбор: найденные «исполнитель + название» ищутся во всех включённых источниках и играют из YouTube/SoundCloud/локальных файлов |
| ❄️ **Холодный старт** | Даже у нового пользователя выдача непустая: профиль засевается из локальной библиотеки, а при полностью пустом профиле — из мирового чарта |

> Deezer здесь используется **только как граф похожести** (related / top / chart). Аудио из Deezer не берётся (их публичный API отдаёт лишь 30-сек превью) — звук всегда приходит из YouTube / SoundCloud / Yandex / локальных файлов.

## Опционально (расширяет, но не требуется)

| Подключение | Что добавляет | Где включить |
|---|---|---|
| **Yandex Music** (токен) | Полный каталог, прямой поток, радар новинок | Настройки → Yandex Music |
| **Last.fm** (API-ключ) | Более богатый граф похожести + жанровые «Открытия недели» (теговый TF-IDF, 2-хоповый обход) | Настройки → Last.fm |
| **Spotify** (ключи API) | Дополнительный каталог для поиска | Настройки → сервисы |

Существующие пользователи Last.fm получают прежнее поведение: при наличии ключа Last.fm приоритетнее Deezer.

## Возможности

- 🎧 **Мультиисточники** — поиск и воспроизведение из YouTube Music, SoundCloud, Яндекс Музыки, Spotify и локальной библиотеки
- 🎨 **Дизайн-система Cryon** — тёмный «фиолетовый глассморфизм», адаптивная раскладка (десктоп-сайдбар / мобильная нижняя навигация)
- 📱 **10 экранов**: Главная, Поиск, Библиотека, Коллекция, Плейлисты, Умные плейлисты, Избранное, История, Жанры, Настройки
- ▶️ **Полноценный плеер**: очередь, перемотка, эквалайзер, waveform-визуализация, тексты песен, MediaSession API
- 🧠 **Рекомендации** — единый кросс-источниковый движок на Go: граф похожести (Deezer/Last.fm) даёт кандидатов, обратная связь (лайк/дизлайк/скип) уточняет вкус
- 💾 **SQLite** — локальное хранилище библиотеки, плейлистов и истории
- 🌐 **Стрим-прокси** — локальный HTTP-сервер на Go для same-origin стриминга аудио

## Архитектура

```
Cryon2/
├── main.go                  # Точка входа Wails (embed frontend/dist)
├── app.go                   # Основные методы, биндятся во фронтенд
├── localserver.go           # HTTP-сервер: стрим-прокси + локальные файлы
├── oauth.go, yandexlogin.go # Авторизация во внешних сервисах
├── internal/
│   ├── domain/              # Модели: трек, артист, плейлист
│   ├── core/                # Ядро приложения (общее для Desktop и Android)
│   ├── services/            # Адаптеры источников (domain.MusicService)
│   │   ├── youtube/  soundcloud/  spotify/  yandex/  local/
│   │   ├── deezer/          # Бесключевой граф похожести (только рекомендации)
│   │   └── registry.go      # Реестр сервисов
│   ├── playback/            # Контроллер воспроизведения (mpv / HTML5-фолбэк)
│   ├── recommendations/     # Движок рекомендаций
│   ├── store/sqlite/        # SQLite-хранилище
│   └── config/, logging/, trackmeta/, websearch/
├── mobile/                  # gomobile-поверхность: встроенный сервер для Android
├── android/                 # Автономная Kotlin-оболочка (WebView + AAR)
└── frontend/
    ├── src/
    │   ├── pages/           # Экраны приложения
    │   ├── widgets/         # Layout, плеер, навигация
    │   ├── shared/          # API-клиент, UI-примитивы, утилиты
    │   └── store/           # Zustand-сторы (плеер, UI, эквалайзер)
    └── dist/                # Сборка фронтенда (embed в Desktop и Android)
```

**Ключевая идея фронтенда**: `shared/api/client.ts` прячет весь бэкенд за функциями с проверкой рантайма и мок-фолбэком — экраны не знают, откуда приходят данные. Это позволяет запускать UI на моках (Vite dev), в Wails (десктоп) и по HTTP (Android) без изменений в экранах.

**Общее Go-ядро**: логика бэкенда живёт в `internal/core` и переиспользуется и десктопом (Wails), и Android (gomobile). Поэтому изменения движка рекомендаций попадают в APK автоматически — отдельного Android-кода для этого не требуется.

## Сборка из исходников

### Требования

- **Go** ≥ 1.26
- **Node.js** ≥ 20
- **Wails CLI**: `go install github.com/wailsapp/wails/v2/cmd/wails@latest`
- Для Windows: [WebView2 Runtime](https://developer.microsoft.com/en-us/microsoft-edge/webview2/)

### Режим разработки (только фронтенд, на моках)

```bash
cd frontend
npm install
npm run dev          # Vite dev-сервер
```

### Desktop-приложение (Wails)

```bash
wails dev            # dev-режим с горячей перезагрузкой
wails build          # сборка Cryon2.exe
wails build -nsis    # сборка + NSIS-установщик (как в CI)
```

Готовый билд: `build/bin/Cryon2.exe` (+ NSIS-установщик).

### Android (автономный APK)

Нужны JDK 21, Android SDK + NDK, Go 1.26 и `gomobile init`. Скрипт собирает всё: фронтенд → `mobile/dist` → `gomobile bind` (`.aar`) → Gradle:

```bash
powershell -ExecutionPolicy Bypass -File scripts/build-android.ps1 -Tag v0.0.0
adb install -r dist/Cryon2-v0.0.0-android-arm64.apk
```

APK: `android/app/build/outputs/apk/debug/app-debug.apk` (плюс копия в `dist/`). Точные шаги — в [plan-android.md](plan-android.md).

### Тесты

```bash
go test ./...                        # Go
cd frontend && npm run test          # Vitest (unit)
cd frontend && npm run test:e2e      # Playwright (e2e)
```

## Сторонние сервисы и приватность

- Приложение обращается к публичным сервисам: **YouTube** и **SoundCloud** (поиск и аудио, без ключей), **Deezer public API** (только граф похожести для рекомендаций — без аудио), опционально **Yandex Music**, **Last.fm**, **Spotify**.
- **Секреты не встраиваются в сборку.** В `.exe`/`.apk` нет зашитых API-ключей: опциональные токены вводятся пользователем локально и хранятся только на его устройстве (SQLite). Публичные бесключевые источники ключей не требуют.
- Публичные API третьих сторон могут менять формат ответов или вводить троттлинг — это внешняя зависимость вне контроля проекта.
